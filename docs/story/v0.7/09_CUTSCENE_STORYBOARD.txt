WRITING RULES
A scene should have a purpose, something that changes, and a specific memory where relevant. Not every scene needs a choice or reward. Use hesitation, humor, interruption and silence; avoid everyone speaking like a counselor. A character's misunderstanding must remain their attributable belief, not an altered fact.
Late caregiver exchange 'You used to tell me the whole game' / 'You only asked if we won' requires recorded prior sharing and score-only questions. Otherwise author a different conversation. Human characters never know private fish reflections without recorded disclosure. Optional crush remains age-appropriate, friendship-equivalent and outside week-one romance scope.

RENDERER / SAVE CONTRACT
Separate scene definition (contentVersion, occurrence slot, nodes, assets, predicates) from scene instance (occurrenceKey, selected variant, evidence snapshot, nodeId, lineId, textRevealed, decisions, revision). Node/line IDs stable within pinned version. Every presented line checkpoints its cursor/reveal state; persist full-text revealed vs typing state, not each character. Reload restarts typing at that same line if interrupted, preserving committed choices. No opaque animation callback may own progression or rewards.
Allowed nodes: line, choice, presentation, activity_handoff, end. Predicate and effect names come from code-owned registries; content cannot execute code, HTML or arbitrary URLs. Relative asset IDs resolve through a validated asset manifest. No remote scripts or external dialogue model.
Scene transitions and effect-bearing choices use existing atomic occurrence/step/effect rules. Authoritative effects occur at declared semantic commits, never on render, portrait change, audio end or scene re-entry. Read-only transcript and replay cannot write effects, unlock facts or reschedule commitments.
Input modes: typing / line_ready / choice_ready / saving / activity / paused / complete. First advance reveals typing text; next explicit advance goes to next node. Opening a choice requires a NEW pointer-down gesture after the triggering pointer-up has completed; never reuse the tap that advanced dialogue. Keyboard events similarly require release before choice activation. Ignore duplicate pointer IDs/multitouch; disable choice submission while saving. Stale/double submissions return prior committed result or conflict, never another effect.
Fast-forward may advance presentation and dialogue, but stops at EVERY unanswered choice, activity handoff or missing required asset. It cannot select a default or synthesize an answer. 'Skip dialogue' presents a concise recap then the next unanswered choice; no whole-scene skip bypasses decisions. Choice-less scene completion still uses an idempotent terminal transaction. Replay skipping does not mark canonical nodes seen.
Background/rotation/pause cancels active pointer sequences and pauses audio/animation. Cutscene input cannot leak to soccer: release all pointers, clear held state and require fresh gameplay input after handoff. Activity launch token persists once and binds activityRunId; retry cannot launch a second canonical activity. Resume returns to activity or its committed outcome, not both.
Missing portrait/background uses approved neutral placeholder without changing identity; missing essential scene node/version or invalid choice fails safely into recovery, not auto-completion. Pin versions through updates; migration maps exact nodes/choices, preserving backup. Audio optional; missing audio never blocks text.
