# SoccerMaster coach review

Open `SoccerMaster_Coach_Review.xlsx` in Excel after extracting this entire ZIP. Keep the workbook beside the `previews` and `assets` folders. Relative preview links may be restricted by mobile spreadsheet apps; if so, open `OPEN_ALL_PREVIEWS.html` in a browser or use the PNG folder for base-state boy previews.

## Review procedure

1. Review each source and its stated limitations on Source evidence. These sources support principles; the authored game situations are adaptations, not source-approved reproductions.
2. For every D01–D36 situation, review base and changed cues in Tactical checks, all four answer grades and feedback in Answers and feedback, and all eight linked previews (both protagonists, before and after).
3. Record corrections in the amber fields. Pay particular attention to whether pressure permits waiting/scanning, whether several actions are defensible, offside at pass contact, realistic cover and recovery, and threats outside the cropped view. Do not approve a cue merely because its caption says it is true.
4. Mark each of the six checks Pass, Revise or Reject. Pass means the current version is acceptable, not that an intended future correction is acceptable. Keep open corrections counted on Coach sign-off. Enter zero explicitly only when none remain.
5. On Coach sign-off, enter your name, qualifications or relevant coaching experience, date, reviewed version hash (copy the required hash only after reviewing it), decision and signed name. Typing your name attests: “I personally reviewed both variants, all proposed answers, coaching feedback, source adaptation and static previews for this situation, and the decision recorded is mine.”
6. Return the workbook with any marked-up previews. Corrections must be implemented and re-reviewed before approval is recorded for a revised version. The required hashes identify the supplied episode JSON. The source-package SHA256 in REVIEW_PACKAGE_ID.txt identifies the full art/content package being reviewed; use both together. Never carry approval to changed assets or content automatically.

## Approval scope and limits

All 36 situations start Pending. No signature, credential or approval has been supplied on anyone's behalf. “Approval recorded” is a worksheet completeness result based on coach-entered information, not identity authentication, governing-body certification or software release approval. The coach or project owner must verify the completed record before changing game metadata.

This is a tactical-content and static-art review, not validation of animation, interception timing, dynamic offside, collision physics, iPhone behavior or grading integration. Those still need runtime tests. Do not change gameplay, progression, rewards or story navigation from workbook entries alone. No game files have been changed.

The original library content is included unchanged. SHA256_MANIFEST.json belongs to that original content; this review workbook and instructions are additional files. Review fields are deliberately blank or Pending. The workbook's approval logic was tested for incomplete sign-off, a complete test record and open corrections; test records were removed. Worksheet samples were visually checked. Native Excel/iPhone behavior has not been tested.
