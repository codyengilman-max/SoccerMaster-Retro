# Tactical Moments (framework v1, drafts for owner review)

Moving, slowed-down versions of the coach-approved All36 situations. Owner brief 2026-11 (pasted in session). **Nothing here is player-facing until the owner approves a specific scene version.** Weekly Team Training is unchanged for players.

## Sequence

Brief → Watch → Slow → Decide → Result → Learn → Retry/Continue, on one scene clock (`src/game/training12/moments/director.ts`).

| Stage | What happens |
|---|---|
| Brief | Coach Code gives the objective (the package's second cue line). |
| Watch | The drafted lead-in plays at 1× (`watch` timeline). Pause and Replay are available. |
| Slow | The same clock runs at 0.35× from `slow.from` to the decision. |
| Decide | The clock stops at the package decision picture; the full state is captured before input. 2–4 package actions, neutral lettered field markers on options that move the ball, Hint (records the attempt as assisted). |
| Result | The chosen branch plays from the snapshot at 0.5×. The stage label says RESULT; the speed is shown separately. |
| Learn | Coach Code: what mattered → what you chose → what changed → what to do next; replay of the branch; arrows/shaded space only from the branch's `annotations`. |
| Retry/Continue | Retry replays the situation from its start (recorded as a retry); Continue returns. |

No runtime AI or language-model call: every lesson, answer, grade, citation and approval comes from the stored data.

## Data

- `scenes.v1.json`: 72 scene versions (36 situations × base/changed), generated by `draft.ts` and stored; `tests/momentsExport.test.ts` fails if the file and the generator disagree (`WRITE_MOMENTS=1` regenerates it, plus `REVIEW_MATRIX.md` and `GAPS_BY_SCENE.md`).
- World space: metres on the package field (45.72 × 68.58), x from the left touchline, y from the home goal line, home attacks +y (up the screen); time in seconds.
- The All36 records in `docs/training/all36/package` are untouched; every scene stores the library id, variant, version and archive hash.
- `approvals.json`: owner approval records `{ sceneId, version, hash, status, reviewer, date, note }`. Empty. A record only counts when its hash equals the scene's current content hash, so any material change voids it (reads as CHANGES_REQUESTED).

## Review status

DRAFT → READY_FOR_REVIEW → APPROVED, with CHANGES_REQUESTED. Generated scenes are READY_FOR_REVIEW when the validator passes (all 72 do), never APPROVED. Player-facing needs: an approval record for the exact hash **and** zero release blockers (validator errors + release-blocking animation gaps).

## Validation (`validate.ts`)

Library id/version/hash; protagonist is the package protagonist and not a keeper; the frozen picture equals the package positions, ball and owner (±5 cm); every branch resumes from the snapshot; branch ball endpoint, owner and package actor targets reached; feedback text equals the package; no player faster than 7 m/s or ball faster than 20 m/s between keys; a held ball stays within 1 m of its holder; passes on the pass contact frame with the foot that faces the target; receptions on the receive contact frame within 1 m of the ball.

## Migration and rollback

- No save schema change. Credit uses the existing `all36Weekly` action, so weekly requirements and reward formulas are unchanged; nothing is credited until a scene is approved.
- Rollback: delete the scenes/approvals JSON imports' consumers (`WeeklyTrainingScene` hand-off line and the Start dev button) or revert the PR; saves are unaffected because nothing new is written.
